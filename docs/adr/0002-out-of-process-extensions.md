# ADR 0002：扩展走进程外 JSON-RPC

状态：提议（2026-11-27）

## 背景

内核不认识任何外部系统，外部系统都由扩展接入。扩展形态有三种选择：语言内插件（Go plugin / 动态库）、嵌入脚本（Lua、WASM）、独立进程。

## 决定

扩展是独立子进程，与内核经 JSON-RPC 2.0 over stdio 双向通信（协议见 `spec/03`）。

## 理由

- **语言自由**：内核用 Go，扩展可用 Go / Python / TypeScript 任意语言写。开源后贡献者不必学 Go 就能写适配器。
- **隔离**：扩展崩溃、阻塞、内存泄漏不影响内核；超时可终止进程。语言内插件做不到。
- **边界天然是 JSON**：「持久化与跨进程边界严格 JSON」「扩展之间不互相 import」变成协议层面的事实，而不是靠守门测试维持的约定。
- **跨平台**：Go plugin 不支持 Windows；动态库分发复杂。子进程 + stdio 三平台一致。
- **可测**：一致性测试套件用录制 fixture 驱动任意语言的扩展。

## 代价

- 每次调用有序列化与进程间通信开销。对分钟级的闹钟轮询与人工速度的对外写可忽略。
- 多一层生命周期管理（启动、崩溃重启、退避、版本协商）。
- 调试需要看扩展日志；提供 `craft ext logs`。

## 备选

- **WASM 扩展**：沙箱好，但外部系统 SDK、HTTP、文件访问的生态与调试体验不成熟，v1 不做；协议设计不排斥将来用 WASM 实现同一协议。
- **同进程 Go 接口**：最简单，但把扩展作者限制在 Go，且无隔离。仅参考扩展可以编译进同一仓库，但仍走协议。
