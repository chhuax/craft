# ADR 0001：内核用 Go 实现

状态：提议（2026-11-27）

## 背景

内核是 I/O 密集的编排程序（调子进程、HTTP、SQLite），没有计算热点。它必须在 macOS、Linux、Windows 上运行，被多个宿主的 hook 与 skill 频繁以短命进程方式调用，并带一个常驻 daemon（闹钟、扩展管理、引擎）。作为开源项目，贡献者门槛与分发便利很重要。

## 决定

内核与 CLI 用 Go。SQLite 用纯 Go 驱动 `modernc.org/sqlite`（无 cgo，便于交叉编译）。

## 理由

| 需求 | Go | Rust | Python | TypeScript |
|---|---|---|---|---|
| 单二进制、零依赖分发 | 是 | 是 | 否（要带解释器） | 否（要带 Node 或打包） |
| 三平台交叉编译 | 几乎无痛 | 可以，链接器/target 更麻烦 | — | — |
| hook 冷启动 | 毫秒级 | 毫秒级 | 每次付解释器启动 | 每次付 Node 启动 |
| 并发（闹钟、引擎、执行池、扩展连接） | goroutine | async 心智成本高 | 勉强 | 事件循环 |
| 贡献者门槛 | 低 | 高 | 低 | 低 |

Rust 的优势（内存安全、WASM 沙箱、极致性能）在这里几乎用不上，开发成本约翻倍，收益很小。若团队本来偏好 Rust，也可行，但不推荐。

## 后果

- 引擎包 `internal/engine` 只许标准库，用表驱动测试固定行为。
- 扩展不受语言限制（见 ADR 0002）。
- 需要自建的部分：JSON-RPC over stdio 的双向连接（可用成熟库，也可自写，协议很小）。
- 需要关注的坑：Windows 的子进程与路径处理、SQLite WAL 在网络盘上的行为（明确不支持网络盘）。
