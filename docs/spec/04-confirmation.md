# 04 对外写的分级与确认

状态：v1 草案。

## 1. 原则

1. **本地操作不拦。** 读写文件、查询、切分支、建 worktree、本地提交、跑测试、shell、写本地记录，不增加任何确认。
2. **对外写按后果分级。** 问两个问题：撤得回来吗？会交到别人手里吗？都不会造成问题的直接做，留外发记录；否则先问人。
3. **确认就是问人，不是权限弹框。** 人在场的会话里，模型用宿主自带的提问工具问人；后台 worker 会话里不用宿主提问工具，由人在面板确认或在该会话里直接答复。人答同意后再执行。没人答就停在那里，不会发出去。
4. **不防模型存心绕开确认。** 内核能做的事上限是人的账号在外部系统里本来就有的权限，外部系统有自己的权限控制。不签确认票据、不核验确认来源、不区分有人在场与无人值守。
5. **内核只认级别，不认业务含义。** 动作由扩展在 manifest 里声明 `level` 与 `reversible`，内核按级别处理。组织可以收严（只升不降）。

## 2. 级别

| 级别 | 含义 | 内核行为 |
|---|---|---|
| `auto` | 撤得回、不交到别人手里 | 直接执行；做内容与频率检查，命中降为 `confirm` |
| `confirm` | 会交到别人手里或撤不回来 | 先预览，人确认后执行 |
| `confirm_named` | 高风险，须人点名 | 人必须点名要做的具体对象；每次单独确认，不与其他操作合并 |
| `deny` | 安全底线 | 在执行入口按规则拒绝，人点了也不执行 |

- **组织规则的配置**放在状态目录的 `outbound.json`：`{"organization": {"<动作 id>": "confirm_named"}}`。文件缺省时采用扩展声明；读取失败或值非法时 daemon **拒绝启动**（宁可不启动，也不悄悄放松）；想降级的条目被忽略并记警告。
- **自动发送的默认频率**：每分钟 5 次（滑动窗口，超出降为 `confirm`）。
- **组织规则只升不降**：`auto → confirm → confirm_named → deny`，不允许降级。
- **自动发送的内容检查**：后台自动发送、经 outbox 的评论在执行入口检查内容（本机路径、凭据、堆栈、内网地址）与频率，命中时降为 `confirm`。会话里直接发的由 skill 要求发前自查，路由层只转发、不替模型拦。

## 3. 执行流程

```
craft act <action> --params ...            # 不带 --yes：只预览，不执行
  → 内核调扩展 action/execute {preview:true}，输出预览（要做什么、对谁、可撤销性）
  → 级别为 auto：预览后直接执行（或本次调用即执行）
  → 级别为 confirm/confirm_named：返回 needs_confirmation，附预览
人答同意后：
craft act <action> --params ... --yes      # 内核当场重查事实（不信缓存）、再执行
```

- 命令负责**硬规则检查**与**当场重查事实**，不信缓存。
- 执行前写 outbox 记录，带幂等键；执行后写回执。崩溃后 `action/verify` 核实是否已生效，避免重复发。
- **后台 worker 会话**：确认类动作不直接执行，先生成「待确认记录」，进入 `attention()` 清单（`kind` 含待确认），由人在面板确认或在会话里答复后执行。
- 带 `--yes` 的命令内核不核验「人是否真的答了」（原则 4）；不发明票据机制。

## 4. 内核层面的底线

内核只保留中立的底线；具体领域的底线（如「不推基础分支」「生产环境不部署」）属于对应扩展或预设包，由它们声明为 `deny` 并在 `action/execute` 里按领域规则拒绝。

| 内核层 | 说明 |
|---|---|
| 统计上报不算对外写 | 只发统计服务、不改业务系统的上报不走分级 |
| 合并类动作 | 推荐扩展把「合并」声明为 `confirm_named`，并拒绝合并自己提的变更（扩展在入口查作者与当前用户，相同或查不出就拒绝） |
| 无 `--yes` 一律只预览 | 任何非 `auto` 动作，缺 `--yes` 都不会产生外部效果 |

## 5. 路由层

内核提供的通用入口 `craft act` 只转发到扩展的 `action/execute`，不改写参数与结果。动作的只读/写性质由扩展在 manifest 里登记：

- 登记为只读的动作直接放行；登记为写的按级别处理；
- **没登记的动作按 `confirm` 处理**，不静默放行；
- `--help` 与纯本地命令不经此关口。

## 6. 与 Watch 的关系

Policy 只管「接不接活」，本文管「做不做对外写」，互不引用。worker 会话里建 PR、提测之类的动作，一律走本文的级别，不属于 Watch。
