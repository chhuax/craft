# 从验收场景拆任务

标准档、重档在返回的 tasksFile 写 Markdown，文件头为单独三行 `---`、`craft: 1`、`---`。一项任务完成一件能窄验证的行为。被后续任务调用的接口先定签名，函数体留到实现时写。每个 S-n 至少有一项任务负责。

任务 ID 用小写字母、数字和连字符。依赖填「无」或前置 ID。目标文件列项目内具体路径，包括测试。验证写反引号包住的命令与可观察结果。 [完整任务卡](../examples/standard-feature/tasks.md)

每次提交说明单独一行写 `Task: <变更编号>/<任务ID>`。运行 `craft method tasks`，done 是已有提交的任务，remaining 是剩余任务，committed 给出对应提交。doneError 表示缺少可用基线，此时无法判断完成情况。清单丢失时按契约重建，保留原 ID 才能对应历史提交；人要求重做某项时给它新的 ID。
