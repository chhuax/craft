# 合并接口与库表的增量

先读项目中该能力的现状，用相同的能力名和合并键。在方案的「接口与库表变更」节，每个三级标题是一项能力，四级标题给出动作和键。例如：

```markdown
### 目录
#### 新增 GET /names
按名称前缀查询。未给前缀时保留原顺序。
#### 修改 name_index
每行以名称和所在目录为联合键。旧记录沿用原目录。
```

动作可用「新增」「修改」「删除」。接口的键是大写方法和路径，表的键是表名。正文写变更后的完整定义。接口列出输入、输出、失败、权限和重复调用的结果；库表列出字段、约束、旧数据处理和回退。配置项用「配置」标记，留在方案里。

用 `craft method archive` 合并，再核对返回的文件与实际差异。重复执行相同增量不会重复创建条目。若新增键与既有正文冲突，先核实哪一份准确，保留人工修订。生成交付说明用 `craft method note`，逐项核对守护测试和证据状态。
