# 按主类型写行为契约

| 类型 | 写清的行为与证据 |
|---|---|
| defect 缺陷 | 现象、期望和期望的出处。用文件、行号与因果链定位根因，保留修复前失败、修复后通过的复现，以及一条不变行为。复现条件不足时说明推断依据。 |
| feature 新增能力 | 每条规则配正例、反例或边界，逐条对应验收与测试。 |
| behavior-change 改已有行为 | 并列写出旧行为、新行为、不变行为。检查已有数据与调用方能否继续使用。 |
| tech 技术改造 | 先用表征测试固定行为。有性能目标时保留相同条件下的基线与改后测量。 |
| data 数据与配置 | 给出执行前后状态、重复执行结果、回退方式及演练证据。 |
| ui 前端页面 | 描述页面、操作、可见结果。分别验证算法、组件、真实交互和用户验收。 |
| cross-repo 跨仓库 | 提供方先定接口，双方引用同一份契约，各自验证并提交。 |
| explore 探索 | 列要回答的问题。结论附实验或代码依据，交付实现另建变更。 |

一次工作兼有多种类型时，用影响最大的类型组织文档，其余风险写进验证计划。
